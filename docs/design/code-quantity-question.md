# Code-authored question for a proven minute-allocation conflict

This is limited to the recorded 45-minute total versus fixed 20/15/15-minute items and
the same-task 50-minute choice. No new natural-language parser or model judge is added.

The unsafe direct proposal is still rejected. Before a model repair, code can author a
clarification only when all the following hold:

- The sole meaning error is `unsafe_direct` with `unresolved` and `no_answer` blockers.
- Grounded obligations and effective relations identify one answer-only requirement,
  with no tool capability, information need, required lookup or external change.
- A new task uses this user request alone, or a linked task is the current active task
  and every carried condition has verified original-user provenance.
- Existing requirement grouping/merging and `evaluate_quantity_group` prove one flat
  minute group with two or more items exceeding its total. Nested/parallel scopes,
  other units, remainder groups and unproved relations are excluded.

The replacement proposal contains a question generated by `relation_question` from that
proof, not the model's unresolved prose. It enters the existing clarify/verdict path.
No unsafe direct answer is delivered, no requirement value is changed, and no design
repair or executor model call is needed to ask the question.

The existing versioned task JSON stores `quantity_questions`: proof, alternatives,
original-user source IDs, task ID, instruction version, request ID and the actual saved
assistant response ID/text. These bindings are validation-only metadata, excluded from
the designer's wire payload. A choice must reference the latest response of the same
task/version. Another task or an old question cannot authorize it. Bound originals are
checked through the existing carried-condition verifier even if the next model omits
them from its constraints; current values are merged and answer numbers are rechecked.

The fixture is a field projection of the actual failed response with a provenance SHA.
Its arguments and message text are replayed at the provider boundary without ID edits.
Only the inbound user event receives its original ID through normal persistence. All
task creation, question persistence and follow-up processing use the real AgentLoop.
Other proposals and error variants are explicit mocks. These tests do not validate a
model's natural-language interpretation or latency.

The prospective real test is just one new conflict→question→same-task 50-minute choice
pair, bounded to four actual sends and 240 seconds including internal correction calls.
`scripts/quantity_conflict_trial.py` defaults to offline preparation. It reuses the pinned
90-second harness, auth/import/commit checks, serial cleanup guard and observed cost
stop: no next request at $0.50 or after any unknown request cost. An in-flight request
can exceed that threshold. Execution requires separate user approval and frozen hashes.
The successful 60→45-minute real scenario is not repeated. No timeout, output limit,
reasoning, model, operating configuration or deployment change accompanies this patch.
