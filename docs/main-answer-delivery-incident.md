# 메인 답변 중단 점검 — 2026-10-23

## 확인된 사실

메인 설정 `.local/config.json`에서 `contextSelection.enabled`는 기본값 false다.
단계적 추론 및 lightweight task note도 비활성이다. 따라서 새 컨텍스트 선택기의
설계·자료 게이트나 지니 전용 작업 완료 검사가 이번 세 턴을 중단한 경로는 아니다.

메인 로그와 원본 세션에서 다음을 확인했다. 개인 식별자와 도구 인자는 보고서에 싣지 않는다.

| 시각(KST) | 관측 | 기존 실행 약속 가드 재현 |
| --- | --- | --- |
| 12:57~12:58 | 상세 사용법 요청 → exec/web_fetch → 안내와 설정 주의사항만 있는 79자 최종 응답 | false |
| 13:03 | 답변 누락을 지적한 후속 요청 → skill_decision → 60자 안내문 종료 | false |
| 13:06 | 정리 중인지 묻는 후속 요청 → skill_decision → 60자 안내문 종료 | false |

이 기록에는 숨은 `CORRECTION` 메시지나 가드의 `INCOMPLETE` 최종 문구가 없다.
실행 중이던 코드의 수정 시각은 프로세스 시작보다 앞서 있으며, 현재 코드로 해당 응답을
판정했을 때도 실행 약속 가드가 발동하지 않는다.

지니의 보고 중 다음 내용은 현재 코드/기록과 다르다.

- `_ACTION`에 `알려`가 없다. `_EXPLAIN`에는 `방법.*알려`가 있다.
- `정리합니다`는 `_PROMISE`에 해당하지 않는다.
- 문장 구분은 현재 `. ! ? 。 ！ ？`와 줄바꿈을 이미 처리한다.
- 따라서 “이번 세 턴이 숨은 교정 1회 뒤 조기 완료 가드에 의해 종료됐다”는 설명은 재현되지 않는다.
- 반복 가드도 이번처럼 서로 다른 문장으로 이루어진 짧은 응답을 잘라내지 않는다.

## 확인된 종료 경로와 남은 불확실성

`AgentRunner`는 기록용 도구만 호출하면서 비어 있지 않은 텍스트를 반환하면
`observability_final` 최적화 경로에서 그 텍스트를 최종 답변으로 인정한다.
13:03과 13:06의 `skill_decision` 기록이 여기에 해당한다.
일반 최종 응답 경로 역시 설명 본문이 실제로 포함됐는지 확인하지 않으므로 12:58의
짧은 안내를 정상 종료로 받아들인다.

즉 **모델이 전달한 안내를 완료된 답변으로 수용하고 추가 답변 생성을 하지 않는 것**이
기록으로 확인되는 애플리케이션 측 결함이다. 해당 최적화는 이번 컨텍스트 선택 커밋에서
처음 추가된 것이 아니라 이전 `5a3050ec` 커밋부터 존재한다.
모델이 왜 본문 대신 안내를 생성했는지(프롬프트/이력 영향, 모델 자체의 응답 경향 등)는
이번 오프라인 검증만으로 단정하지 않는다.

## 적용한 최소 수정

- `answer_delivery.py`: “정리합니다” 같은 **명백한 답변 예고**와 본문이 누락된 형태만 좁게 판정한다.
  글자 수만으로 답변을 거부하지 않는다. 이미 전달된 짧은 사실 답변, 항목/코드가 있는
  안내, 일반적인 진행 상태, 실제 접근 불가, 사용자 입력을 기다리는 조건부 설명은 보존한다.
- `runner.py`: 일반 final 및 기록용 도구 final 두 분기에서 같은 본문 복구를 수행한다.
  사용자에게 본문 누락과 이어 작성을 알리고 기존 제공자/도구 루프로 복귀한다.
  두 번째 예고문에도 한 차례 더 기회를 주며, 최대 **2회**·남은 반복 예산 안에서만 복구한다.
  필요한 승인된 도구는 사용할 수 있지만, 이미 성공한 작업의 불필요한 재실행이나
  새 권한/다음 단계 승인으로 확대하지 않는다.
- 복구가 실패하거나 예산이 없으면 실제 부분 응답을 남기고 미완료 사유와 시도 횟수를 표시한다.
  예산 소진 후의 기존 최종 정리 호출도 예고문을 완성 답변처럼 표시하지 않는다.
- `loop.py`: 내부 본문 복구 지침을 사용자 원문/지속 기억으로 저장하지 않는다.
  실제 사용자 요청, 모델 출력, 도구 연결과 원본 기록은 보존한다.
- `premature_final.py`: 기존 조건부 사용자 단계 처리를 보존하고,
  구두점 없이 끝난 한국어 문장 뒤 `지금/이제/먼저/다음으로`로 시작하는 별도 문장의 경계를 보완한다.
  모든 `다` 글자를 문장 끝으로 취급하거나, 실제 미실행 작업 약속을 무조건 통과시키지 않는다.

기존에 작업 중이던 task note/진행 표시/도구 변경을 덮어쓰지 않았다.
컨텍스트 선택, 모델 프리셋, 권한 설정과 다른 페르소나는 변경하지 않았다.
