# 기억 상한과 원문 검색 분리

`agents.defaults.memoryPromptTokens`는 **기본값 0(비활성)** 이다. 양수이면
`memory/prompt_snapshot.json`의 검토된 짧은 기억을 사용한다. 원본 `memory/MEMORY.md`,
대화 원문 DB, 기존 검색·원문 읽기 도구는 그대로 유지한다.

## 보존 조건

- 기본 모드에서는 사람이 현재 원문을 검토해 짧은 기억을 준비한다. 활성 권한·금지·
  선호·정정은 반드시 보존해야 한다. 수동 생성 명령은 의미의 충실도를 자동 검증하지
  않는다. 아래 자동 갱신은 별도로 켜야 하며 기본값은 비활성이다.
- 원문의 SHA-256이 일치하고, 안내문·기억 제목을 포함한 예상 토큰이 상한 이내인
  검토본만 사용한다. 일반·compact·후속 대화에서 같은 검토본을 사용한다.
- Dream 또는 사용자가 원문을 바꾸면 기존 검토본은 즉시 무효가 된다. 수동 모드에서는
  다시 검토해야 하며, 자동 모드에서는 백그라운드 생성·검토를 요청한다. 오래된
  검토본에 새 원문 해시만 덧씌우면 안 된다.
- 손상·누락·상한 초과·접근 실패 시 경고를 남기고 **기존 기억 로딩으로 복귀**한다.
  요청을 막거나 기억을 잘라 버리지 않는다. 이때 기존 경로는 상한을 초과할 수 있다.
  복구 가능한 절감 목표이며 전체 프롬프트/비용의 강제 상한은 아니다.
- 토큰은 기존 추정기를 사용한다. 제공자별 정확한 토큰/전체 호출 비용 보장은 아니다.
- 파일 도구가 비활성화되었거나 다른 프로젝트 문맥이면 검토본을 사용하지 않는다.
  원문을 찾아볼 수 없는 상태에서 기억만 생략하지 않는다.

## 검토본 준비와 적용

운영 파일부터 바꾸지 말고 후보를 별도 경로에 만든다. 활성 정책은 우선 그대로
보존하고, 생략 가능한 과거 기록·참고 자료만 원문으로 남기는 보수적 정리부터 한다.

```bash
.venv/bin/python scripts/prepare_memory_prompt.py \
  --workspace /path/to/workspace --summary /path/to/reviewed-memory.md \
  --budget 2000 --out /path/to/candidate.json
```

이 명령은 원문이나 운영 설정을 변경하지 않는다. 예산을 초과하면 쓰기 전에 거절한다.
검토를 통과한 JSON을 해당 워크스페이스의 `memory/prompt_snapshot.json`으로 배치하고,
그 워크스페이스의 설정에 같은 `memoryPromptTokens`를 명시해야 활성화된다.
2000은 명령 예시이며 현재 기억의 활성 제한을 보존할 수 있는 값으로 정한다.
공용 기본값이나 다른 에이전트의 설정을 한꺼번에 변경하지 않는다.

## 자동 갱신 (선택)

해당 워크스페이스의 설정에 다음을 명시하고 게이트웨이를 재시작한다.

```json
{"agents": {"defaults": {"memoryPromptTokens": 5000, "memoryPromptAutoRefresh": true}}}
```

- 다음 문맥 생성 시 원문 변경·검토본 누락/손상을 감지한다. 현재 요청을 기다리게
  하지 않고 최신 원문을 사용하며, 백그라운드에서 검토본을 갱신한다. 이후 문맥부터
  새 검토본을 사용한다. 유효한 검토본이 있으면 추가 모델 호출은 없다.
- 원문 전체가 예산에 들어가면 요약 없이 그대로 복사한다(모델 호출 없음). 이전
  원문 전체의 SHA-256이 현재 원문의 앞부분과 정확히 일치하고 끝에만 내용이 추가된
  경우, 기존 검토본에 추가 원문을 그대로 붙인다. 더 작은 쪽이 예산 안에 들어가야
  하며, 중간 수정·삭제·다른 버전의 근거를 이 방법으로 통과시키지 않는다.
- 새 요약이 필요하면 현재 설정된 채팅 제공자·모델로 생성과 별도 대조 검토를 한다.
  이전 검토본이 있으면 그 문자열에 대한 정확한 수정 목록을 받는다. 모호하거나
  없는 문자열의 수정은 거절하며, 수정은 메모리 안에서만 수행한다. 이전 요약은
  현재 권한의 근거가 아니며, 결과를 전체 최신 원문으로 다시 대조한다.
  상한 초과나 검토 지적이 있으면 딱 한 번 보완한다. 상한 초과 후보는 검토·적용하지
  않는다. 재보완 후에도 실패하면 원문을 유지한다. 정상 2회, 보완 포함 최대 4회 호출한다.
  보완은 직전 후보에서 정확했던 내용을 유지하며 지적된 부분을 고친다. 기존 검토본이
  없으면 전체 요약을 생성하고 같은 예산·검토 조건을 적용한다.
  다른 제공자/사이트, 대화 내역, 도구, 외부 전송 기능은 추가하지 않는다. 원문 기억은
  평소 프롬프트와 같은 제공자에게 전달된다. 모델 기반 의미 검토는 완전한 보장은
  아니므로 원문 검색과 안전한 실패 경로를 유지한다.
- 검토는 금지·선호·정정·조건·역할 경계의 보존, 원문 충실도, 새로운 승인/권한이
  생기지 않았는지를 각각 확인한다. 하나라도 실패하거나 응답이 잘리면 적용하지
  않는다. 최종 안내문을 포함한 추정 토큰도 기존 예산을 통과해야 한다.
- 작업은 최대 180초, 모델 자체 재시도는 없고 동일 원문 실패 후 5분간 재시도를
  제한한다. 재시도는 이후 문맥 생성 때 수행한다. 프로세스 내부 중복 방지와
  워크스페이스 파일 잠금으로 겹친 호출을 막는다. 종료 시 작업을 취소한다.
  유지보수 호출에만 낮은 추론 강도를 명시한다. 일반 채팅의 모델·추론 설정은 바꾸지 않는다.
- 원문이 128KB보다 크거나 안전하게 읽을 수 없으면 원문 경로를 유지한다. 파일
  도구 비활성·예산 0·다른 프로젝트 문맥에서는 실행하지 않는다.
- 원문은 수정하지 않는다. 생성 중 원문이나 수동 검토본이 바뀌면 결과를 버린다.
  검토본은 워크스페이스 안의 고정 경로에 권한 0600으로 원자적으로 교체한다.
  실패 시 기존 검토본 파일을 유지하고 최신 원문을 계속 사용한다.

자동 생성 파일은 version 2의 `summary_chunks` 배열에 문자열을 저장한다. 각 문자열은
최대 1024자이며 순서대로 구분자 없이 이으면 원래 요약과 정확히 같다. JSON 한 줄이
출력 제한보다 길어서 읽기를 반복하는 문제를 피하며, `read_file`의 기본 제한이나
완료 판정 기준을 완화하지 않는다. 기존 version 1의 `summary` 문자열도 계속 읽는다.
외부 확인 스크립트는 버전에 따라 `summary` 또는 `''.join(summary_chunks)`를 읽어야 한다.
수동 준비 스크립트의 기존 출력 형식은 유지한다.

로그의 `Memory prompt refreshed`로 완료를, `Memory prompt refresh deferred`로 실패
단계·안전한 원인 코드와 재시도 대기를 확인한다. 토큰 초과는 추정치와 상한을 함께
기록한다. 원문·요약·자격증명은 이 로그에 남기지 않는다. 검토본의 `refresh` 필드는
생성 방식·모델·시각·시도 횟수·추정 토큰을 기록한다. 자동 갱신만 취소하려면
`memoryPromptAutoRefresh`를 `false`로 되돌리고 재시작한다. 이후 기존의 수동 검토본
동작으로 돌아간다.

검토본 안내에는 원본 경로가 남는다. 현재 대화에 없는 필요한 상세만 `search_memory`로
찾고, 정확한 문구가 필요하면 `read_memory_events`를 사용한다. 검색 실패·개인별 검색
제외는 전체 원문 읽기의 근거가 되지 않는다. 검색 실패는 확인 불가로 보고한다.
사용자가 원본 파일 읽기를 직접 요청한 경우에는 기존 파일 도구의 권한과 범위를 따른다.
현재 대화에 있는 답은 다시 검색할 필요가 없으며, 생략을 '기록에 없음'으로 단정하지 않는다.

## 짧은 기본 기억의 운영자 전환

`scripts/core_memory_ops.py`는 후보 준비·검사·설치용 수동 도구다. 운영 원문과 설정은
수정하지 않는다. 생성은 기존 모델 생성·별도 검토를 사용하므로 실제 호출 비용이 든다.
검사와 설치는 모델을 호출하지 않는다. 코드 구현만으로 예산을 1000으로 낮추지 않는다.

1. `inspect --workspace W --config C`로 현재 예산·원문 버전·검토본 상태를 읽기 전용 확인한다.
2. 현재 원문을 읽고 비공개 `conditions.json`에 `workspace`(해석된 절대 경로),
   `source_sha256`(원문 텍스트 해시), `required`(허용 표현의 목록을 담은 목록),
   `revoked`(되살아나면 안 되는 표현 목록)를 명시한다. 필드 누락·빈 표현·잘못된 타입은
   거절한다. 조건이 없을 때도 빈 목록을 명시한다. 원문이 바뀌면 조건도 다시 검토한다.
3. `generate --workspace W --staging S --budget 1000 --config C`로 후보를 만든다.
   S는 작업공간 및 Git checkout 밖의 **새 디렉터리**여야 한다. 기존 S를 재사용하지 않는다.
   실패하면 조건을 삭제하지 말고 새 S에 1500 또는 2000 예산으로 재시도한다.
4. `check --workspace W --staging S --budget B --conditions F`로 원문 버전·후보 해시·예산과
   선언된 표현을 검사한다. 이것은 문구 검사이며, 인용·부정·모순의 의미를 보장하지 않는다.
   원문과 후보 전체를 비공개로 직접 대조하여 금지·권한·조건·정정의 의미를 확인한다.
   생성 결과의 `candidate_sha256`는 검토 대상의 식별자이며 그 자체가 승인 증거는 아니다.
5. 의미를 확인한 후보의 해시 H를 지정하여 설치한다:

   ```bash
   PYTHONPATH=. .venv/bin/python scripts/core_memory_ops.py install \
     --workspace W --staging S --budget-now 5000 --conditions F \
     --backup D --reviewed-sha256 H
   ```

   H는 검토한 바로 그 바이트의 SHA256이다. 읽지 않은 후보에 생성 결과 해시를 자동으로
   전달하는 승인 자동화를 만들면 안 된다. 설치는 같은 잠금 안에서 한 번 읽어 검증한
   바이트만 게시한다. D도 작업공간·Git checkout 밖이며 S와 겹치지 않아야 한다.
   백업은 0600의 고유 파일명으로 보존하며 같은 초에 다시 설치해도 덮어쓰지 않는다.
6. 현 예산 5000을 유지한 채 확인한 뒤, 현재 원문으로 다시 `check --budget B`가 통과하고
   품질·입력·검색·갱신 비용이 적절할 때만 해당 봇의 예산을 낮추고 재시작한다.
   다른 봇 설정은 바꾸지 않는다. 예산·검토본의 백업과 복구는 별도 승인된 운영 작업이다.

예산 하향 전 원문이 바뀌면 이전 검토본은 무효이며, 현행 자동 갱신은 계속 별도 모델
검토를 사용한다. 낡은 운영자 조건 목록을 자동 갱신에 강제 적용하지 않는다.
자동 갱신 뒤 의미 보존은 합성 테스트만으로 보장되지 않으므로 실제 후보 확인이 필요하다.
생성·검토는 같은 보존 범위를 사용한다. 현재 시제의 구현 현황도 검색으로 넘길 수
있으며 그 생략만으로 거절하지 않는다. 사용자 제한·승인·철회·선호·역할 경계와 그
규칙을 정의하는 정확한 값은 반드시 남긴다. 후보가 실제로 주장한 사실은 원문과
일치해야 하며, 관찰 사실을 새로운 금지나 권한으로 바꾸면 거절한다.
조건·후보·백업은 비공개 경로(디렉터리 0700, 파일 0600)에 보관하고 Git에 넣지 않는다.

기존 검토본으로 시작하려면 `generate`에 `--reuse-snapshot`을 명시한다. 새 비공개
스테이징에 복사할 뿐 운영 파일은 바꾸지 않는다. 원문 내용이 바뀐 모델 갱신은 현재
원문 전체와 대조하고 별도 검토를 통과해야 한다. 원문 해시가 일치하는 접두부에
추가분만 붙는 경우에는 기존의 무손실 재사용 경로를 유지한다. 오래된 검토본의 권한
문장이나 제한 완화를 신뢰해서는 안 된다. 모델 수정 제안은 전체 원문을 기준으로
기존 문장까지 점검하고, 재수정 입력에는 후보를 한 번만 넣는다. 작은 수정은 기존
`edits`를 사용하고 큰 수정은 `summary` 하나로 새 요약만 반환해 지울 원문 전체를
응답에 반복하지 않는다. 두 형식 모두 같은 예산 검사·독립 검토를 거친다.
추가분 재사용에는 검토 당시 원문·요약의 해시 기록이 모두 맞아야 한다. 이전 형식이나
수정된 요약에 그 기록이 없으면 전체 원문 대조를 거친다. 원문 그대로인 무손실 복사는
별도 의미 검토가 필요 없다. 이 기록은 로컬 검토 이력의 일관성 표시이며 사용자 인증이나
실행 허가가 아니다. 기존 현재 검토본을 읽는 동작은 유지하고, 명시적인 재검토 명령은
해시가 현재 원문과 같아도 검토 기록 없는 압축본을 다시 점검한다.

운영자 `generate`는 비공개 스테이징의 `attempt-N.json`에 완료된 생성·검토 응답을 0600으로
보관한다. 실패해도 거절 사유를 확인할 수 있으나 기억 내용이 포함되므로 외부 공유하지
않는다. 이 기록은 명시적인 운영자 스테이징에서만 생성하며 일반 대화·자동 갱신에는
추가하지 않는다. `refresh_status`는 내용 없이 단계·실패 코드·토큰 추정·검토 결과와
문제 개수만 보여준다. 실패한 기존 검토본 복사는 새 후보로 표시하지 않는다.

자동 갱신에서 예산·품질 검사를 소진하거나 응답이 잘리면 같은 원문·예산·모델로 5분마다
반복 생성하지 않는다. 원문·예산·모델이 바뀌면 다시 시도하며, 운영자가 명시적으로
실행하는 새 스테이징과 프로세스 재시작도 재시도가 가능하다. 네트워크 오류·잠금·시간
초과에는 기존 5분 대기를 유지한다. 그동안 채팅은 중단하지 않고 현재 원문을 사용한다.

`BoundedMemoryPrompt.status`는 매 문맥 생성마다 현재 입력 추정치를 갱신하며
`counts`에 `builds`, `snapshot_builds`, `fallback_builds`, `off_builds`,
`fallback_input_tokens_est`를 누적한다. 이는 **프로세스 내 문맥 생성 횟수**이며
사용자 턴 수나 제공자 호출 수가 아니다. 25회마다 `Bounded memory usage` 합계 로그를
남긴다. 두 요약 사이 카운터 차이로 문맥 생성 중 원문 대체 비율을 계산한다.
경고 줄 개수로 대체 빈도를 추정하지 않는다. 재시작 시 카운터는 초기화된다.

## 6단계: 오래된 중복 도구 출력의 입력 사본 축소

일반 실행 경로는 입력 상한 처리와 도구 쌍 복구를 마친 뒤, 2000자 이상인 과거 참조
출력의 완전 중복만 줄인다. 도구명·인자 문자열·본문이 모두 같고, 동일 본문이 최신
과거 도구 결과로 같은 모델 입력 안에 온전히 남을 때만 이전 본문을 해당 결과의 참조로
바꾼다. 해시가 같아도 실제 문자열을 다시 비교한다. 별도 모델 호출이나 파일 저장은 없다.

최근 두 사용자 턴과 현재 실행에서 생성한 결과는 그대로 보존한다. 숨겨진 런타임
안내는 사용자 턴으로 세지 않는다. 도구 호출 ID와 인자, 사용자 조건·철회, 시스템
메시지, 저장용 원본 대화는 바꾸지 않는다. 중복·누락된 호출 ID, 실패 상태, 근거로
표시된 결과, 작은 출력은 줄이지 않는다.
현재 실행에서 같은 결과가 새로 나와도 기존 과거 참조의 대상을 바꾸지 않아,
이 최적화 때문에 매 반복마다 과거 프롬프트 접두부가 달라지는 것을 피한다.

대상은 web_search, web_fetch, list_dir, find_files, grep뿐이다. read_file, exec,
search_memory, read_memory_events, 수정 도구와 미분류 도구는 보존한다. 선택 문맥
실행은 기존의 별도 검증 경로를 유지한다. 서로 다른 과거 결과를 의미 요약하거나
생략하지 않으므로 반복 출력이 적으면 절감도 없다. 기존의 상한 초과 시 축소 동작은
그대로이며, 이 기능으로 전체 입력·비용 상한을 보장하지 않는다.

## 가벼운 검증과 취소

```bash
.venv/bin/python -m pytest tests/agent/test_bounded_memory_prompt.py \
  tests/agent/test_memory_prompt_refresh.py tests/agent/test_memory_prompt_snapshot.py -q
.venv/bin/python scripts/improvement_eval/run.py --suite core \
  --out .local/evaluations/bounded-memory-core.json
```

프롬프트 변경이므로 격리된 합성 기억으로 단순 답변·생략된 원문 검색·현재 금지 준수
정도만 실제 모델로 추가 확인한다. 운영 기억/자격증명/실제 전송은 실험 입력으로
사용하지 않는다. 대화가 끊기거나 기억이 사라진 것처럼 답하면 활성화를 취소한다.

취소는 `memoryPromptTokens`를 0으로 되돌린다. 검토본을 제거해도 기존 경로로
복귀하지만 경고가 남으므로 설정 해제가 명확하다. 원문을 수정하지 않았으므로
원문 복원이나 검색 DB 재구축이 필요 없다.
